# Neax - Global Skill

# Project Identity

Neax 是一个 AI Native 的个人知识系统。

它不是传统的笔记软件，也不是企业后台系统。

系统的核心目标不是"管理数据"，而是：

帮助用户建立、组织、延续自己的长期思维与知识。

Neax 应当像一个安静、克制、长期陪伴用户的数字书房。

系统必须始终围绕：

记录 → 理解 → 总结 → 检索 → 长期积累

这一核心主线展开。

任何功能、架构、设计、交互，都必须服务于这条主线。

如果一个功能无法增强：

- 知识组织
- 长期记忆
- AI理解能力
- 用户思维连续性

则不应优先开发。

***

# Product Philosophy

Neax 强调：

- 内容优先
- AI 原生体验
- 长期上下文
- 简洁
- 安静
- 可持续迭代

系统不追求：

- 功能堆积
- 企业化后台
- 复杂协作
- 社交化
- "万能平台"

当前阶段：

Neax 是一个：
"小而完整"的 AI 产品。

优先保证：

- 清晰结构
- 可维护性
- 可运行
- 可迭代

而不是：

- 大而全
- 复杂架构
- 提前设计未来能力

***

# Engineering Philosophy

项目必须优先考虑：

1. 低耦合
2. 可维护性
3. 清晰结构
4. AI 可理解性
5. 渐进式演化

禁止为了"高级感"引入过度复杂的设计。

当前阶段禁止：

- 微服务
- 分布式架构
- 复杂中间件
- 过度抽象
- 为未来假想需求提前设计

任何复杂度的增加，都必须有明确理由。

***

# AI Collaboration Philosophy

AI 是项目协作者，而不是代码生成器。

所有 Agent 必须：

- 保持代码结构清晰
- 保持模块边界明确
- 避免高耦合
- 避免隐式依赖
- 避免一次性生成超大规模代码
- 每次只进行一个功能的改进或者修复，不允许一次性修改多个功能或者结构

AI 修改代码时必须：

- 优先理解已有结构
- 尽量局部修改
- 保持风格统一
- 不随意重构稳定模块

禁止：

- 未经确认的大规模重构
- 擅自改变项目方向
- 引入未经使用的复杂设计
- 为"理论最佳实践"破坏当前项目节奏
- 保留大量脚本

***

# Architecture Direction

Neax当前采用：

Frontend:
- vue
- Next.js
- TypeScript

Backend:

- Spring Boot

Database:

- PostgreSQL

AI:

- OpenAI / DeepSeek API

项目架构应保持：

简单
稳定
清晰
易理解

当前阶段：

工程完整性
优先于
架构先进性。

***

# UI Philosophy

界面必须：

- 克制
- 安静
- 内容优先
- 减少视觉噪音
- 亮色优先

用户的"思考内容"必须始终是系统中心。

禁止：

- Admin 风格
- 高信息密度
- 炫技动画
- 花哨视觉设计

Neax 更接近：
"个人知识空间"

而不是：
"企业工作台"。

***

# Scope Control

当前版本必须严格控制范围。

优先实现：

- 笔记
- AI总结
- AI标签
- AI问答
- 搜索
- 基础知识组织

禁止提前开发：

- 多人协作
- 权限系统
- 工作流引擎
- 自动Agent执行
- 复杂RAG系统
- 知识图谱
- 插件生态

功能扩展必须遵循：

小步迭代
稳定演化
逐步验证

***

# Code Philosophy

代码必须：

- 可读
- 可维护
- 职责明确
- 命名清晰
- 注释清晰
禁止：

- 巨型类
- 巨型函数
- 魔法字符串
- 隐式逻辑
- 临时代码长期保留

优先：

简单实现
稳定实现
可理解实现

而不是：

炫技实现
过度设计
理论化架构

***

# Long-term Vision

Neax 的长期目标是：

成为一个真正理解用户长期知识与思维上下文的 AI 系统。

它不仅保存内容。

它还能够：

- 理解知识
- 延续思维
- 辅助创作

但当前阶段：

必须克制。

任何未来能力，
都不应提前透支当前工程复杂度。

***

# Final Principle

始终记住：

Neax 的核心不是"功能"。

而是：

长期知识体验。

所有设计与开发，
都必须服务于这一目标。
